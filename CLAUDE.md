# Sea Glass

**Sea Glass** is a design language that extends Material 3 Expressive with a frosted, diffusing sea-glass material. This repository is a monorepo: the platform-neutral design source lives in `core/`, and each platform implementation lives under `platforms/`. Today there is one platform, Android (Jetpack Compose).

## Layout

```
core/                     platform-neutral; never imports platform code
  tokens/                 tokens.json, palettes.json (source of truth for colour, type, spacing, radius, shape, size, blur, opacity, state, shadow)
  spec/                   spec.md (the design spec), verification.md
  reference/              recipes.js, boards/*.js, animations.css, README.md (exact numbers and geometry)
  assets/                 grain.png, seaglass_photo.jpg, fonts/ (canonical copies)
  codegen/kotlin/         seaglass-tokens.gradle.kts (tokens.json -> Kotlin)
  tools/hct/              hct.py (HCT palette maths)
  tools/verification/     contrast and screenshot capture scripts
platforms/
  android/                Gradle root (open this folder in Android Studio)
    sdk/seaglass/         :sdk:seaglass, the SDK library (namespace com.floydwiz.seaglass)
    sample/               :sample, the showcase app (namespace and applicationId com.floydwiz.seaglasssample)
    benchmark/            :benchmark, macrobenchmarks and the baseline profile generator
    tools/perf/           frame statistics, Perfetto traces, screenshot diff
    docs/                 milestones, progress, performance, showcase and demo notes, verification results
.claude/                  slash commands
```

## Rules

- `core/` is platform-neutral. It never imports or references platform code; platforms read from it.
- Generated files are never hand-edited. Token Kotlin is generated by `core/codegen/kotlin/seaglass-tokens.gradle.kts` from `core/tokens/*.json`; to change a token, edit the JSON and run `./gradlew :sdk:seaglass:generateSeaGlassTokens` from `platforms/android`. `verifySeaGlassTokens` fails the build when generated Kotlin and JSON drift.
- Package names are fixed: the SDK is `com.floydwiz.seaglass`, the sample is `com.floydwiz.seaglasssample`.
- No Google logos, product names or brand marks anywhere in the app or sample content.

## Source of truth

Read these before writing code. Do not invent values that the docs already define.

| File | What it holds |
| --- | --- |
| `core/spec/spec.md` | The full design spec: principles, colour, the eleven finishes, states, shapes, motion, every component, the screens, accessibility modes. |
| `core/reference/README.md` | How to read the reference code and how each CSS layer maps to a Compose API. **Read this before porting any recipe.** |
| `core/reference/recipes.js` | Exact recipe for every finish (`mat()`), every state (`W()`), the focus halo and the contrast modes. The numbers here win over prose. |
| `core/reference/boards/*.js` | Exact geometry of every component specimen (C0–C7) and every screen (412×915 phone, 1280×800 tablet). |
| `core/reference/animations.css` | Keyframes and durations for drift, morph, comet, bob and indeterminate progress. |
| `core/tokens/` | `tokens.json` and `palettes.json`; colours, type and the other token families. Never hand-edit the Kotlin generated from them. |
| `core/assets/` | `grain.png` (noise tile, 200 dp repeat), `seaglass_photo.jpg` (sample imagery) and the canonical fonts. |
| `platforms/android/docs/milestones.md` | The Android build plan. Work one milestone at a time. |

## Android

Open `platforms/android` in Android Studio, or run Gradle from that folder.

- `:sdk:seaglass` — library: theme, shapes, `Modifier.seaGlass(...)`, all components. No app code.
- `:sample` — the showcase: catalogue (one destination per board C0–C7), the Phase 4 screens as working flows, and a control sheet (light/dark, contrast mode, reduce transparency, seed colour, dynamic colour, per-layer toggles, FPS overlay).
- Package layout inside `:sdk:seaglass`: `color/`, `shape/`, `material/` (finishes and the glass modifier), `components/<group>/`, `theme/`.
- Backdrop blur: one shared, downscaled, blurred copy of each `GlassBackdrop` (`material/BackdropBlur.kt`) that every glass element crops with `drawLayer`. Haze was removed: it blurs once per element, about 16 render passes each. Everything else uses standard Compose APIs. See the mapping table in `core/reference/README.md` (its Haze rows are historical).
- Shape morphs: `androidx.graphics:graphics-shapes`, or animate the eight elliptical radii directly.
- Lens magnification: AGSL `RuntimeShader` on API 33+, falling back to scaling the content under the lens.

### Stack and versions

- Check `platforms/android/gradle/libs.versions.toml` and the existing build files first; keep the project's AGP, Kotlin and compileSdk unless something below forces a bump.
- Compose UI **1.9 or later** is required (for `Modifier.dropShadow` and `Modifier.innerShadow`). Use the newest stable Compose BOM that satisfies this.
- Material 3 **1.4 or later** (Expressive APIs, `MotionScheme`).
- Glass blur needs API 31+. If the project's minSdk is lower, glass falls back to the reduce-transparency recipe below API 31.
- Icons: Material Symbols Rounded (variable font with FILL, wght, opsz axes) bundled in `res/font`, drawn through a small `SymbolIcon` composable. If the font can't be downloaded, fall back to `Icons.Rounded` and tell me.
- Type: Roboto Flex (bundled variable font or downloadable fonts).

### Conventions

- Keep code comments minimal: only where the logic is genuinely non-obvious, short and without filler. Larger or complex functions get a brief bullet-point summary above them instead of inline comments throughout.
- Tokens are named `seaGlass.*` in the spec; in Kotlin they live in a `SeaGlassTokens` object tree with the same structure (for example `SeaGlassTokens.Shadow.Tint.Opacity`).
- Every component takes a `role: TonalTones` (defaulting from a `LocalGlassRole`), an `InteractionSource`, and reads contrast and reduce-transparency mode from composition locals. Components never hardcode colours.
- Previews: one `@Preview` per component in light and dark at minimum.

### Verify every change

Run from `platforms/android`.

1. `./gradlew :sdk:seaglass:compileDebugKotlin :sample:assembleDebug` must pass. Fix all errors before moving on.
2. If a device or emulator is connected (`adb devices`), install, launch and capture:
   `adb install -r sample/build/outputs/apk/debug/sample-debug.apk`, then
   `adb exec-out screencap -p > screenshots/<name>.png`, then look at the PNG yourself and compare it with the spec. The `/sg-check` command does this.
3. Note anything you could not verify (for example blur on an API 30 emulator) in your summary instead of claiming it works.

## Working style

- One milestone per session. Plan first, then implement, then verify, then commit with a short message.
- When a value is missing from the docs, choose the closest one that exists, say which you chose, and keep going.
- Keep the showcase honest: if something is approximated (for example the lens magnification fallback), label it in the UI's info text.
